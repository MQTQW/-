# Android 旅行接入 · 2026-11-04

接续 [10 月 30 日交接](HANDOFF-2026-10-30.md)，工作分支仍为 `codex/travel-planner`。本轮源码版本为 1.0.8（9）。本轮将已验证网页流程接入原生 Compose；当前入口是「首页／日历 → 旅行行程 → 找旅行灵感」。

## 本轮实现

城市检索 → 景点、美食、体验候选及攻略图 → 用户加入想去、标记必选 → 出行条件 → 真实 AI 只安排已选内容 → 明确确认后保存为独立行程。分类可为空；缺图不影响文字与出处。未排下内容明确展示，生成失败没有样例回退。未确定日期可以预览，保存到日历前需要确认日期并重新编排。

供应商 Key 保留在电脑服务端，手机只保存独立本机连接码。原生 `/api/native/*` 使用 Bearer、独立 Cookie 和 POST CSRF；网页原有同源检查继续保留。接口默认关闭，显式传入 `--native-token-file` 才开启，仍只绑定电脑 `127.0.0.1`。

Room `travel.db` 从 1 升到 2，通过增量迁移增加 `trips.liveEvidenceJson`，不清空旧数据。保存完整公开来源、生成时地点核对和交通记录，编辑备注只放摘要。行程详情可展开「生成时来源与提醒」；手动编辑不会自动更新历史证据，界面明确注明。保存不会自动创建提醒，仍需用户主动另存。

联网生成的行程每日最多保存 15 个节点，以容纳最多 12 个已选内容和抵达、住宿、返程 3 个固定安排；固定项仍需来自用户填写的条件。原有手动行程继续保留每天 12 个节点的限制。

## 手机连接步骤

1. 电脑配置并启动原有小红书 MCP、DeepSeek、高德服务；缺失配置的恢复方式见上次交接。准备 Node 与 MCP 运行时，Chrome 已安装。
2. 双击根目录 `连接手机旅行服务.cmd`。它生成独立连接码并打开本机说明页。若旧旅行服务已占用端口且尚未启用手机接口，先用「停止旅行服务」关闭该启动器创建的实例，再重新运行。不会接管其他进程。
3. 用 USB 连接本人手机，开启开发者选项与 USB 调试，在手机上确认授权。从 Android SDK platform-tools 执行：

   ```powershell
   adb reverse tcp:8794 tcp:8794
   ```

4. 安装本轮调试 APK，在「找旅行灵感 → 连接设置」填 `http://127.0.0.1:8794` 和电脑说明页的本机连接码，保存后检测连接。无需填写供应商 Key。小红书扫码仍在电脑完成。
5. 选择城市检索与编排。电脑要持续运行，断线后新的检索和编排不可用；这个联调入口尚不支持离开电脑后随身联网使用。

连接码保存在仓库外 `%LOCALAPPDATA%/MyPlanTravel/private-native.json`，与 MCP 令牌互不通用。连接说明页也含连接码，请勿上传 GitHub。手机配置文件 `travel_live_settings.xml` 已排除云备份与设备迁移。调试构建只对既有本机开发地址允许明文 HTTP；正式版仍按 HTTPS 网络策略。

## 恢复边界

屏幕旋转保留 ViewModel 的任务、输入快照与结果。停止查看只停止轮询，不取消电脑任务。进程重启恢复公开候选、选择和条件；不会恢复原 Cookie、运行中任务或未保存结果预览，需要重新连接、检索。保存后的 Room 行程可离线查看，攻略代理图片可能过期。

当前结果页使用每天的列表，保存后沿用原生节点编辑、地图查看与另存提醒；没有新增离线地图、导航、云同步或付费服务器。地图核对只代表地点身份／坐标，交通为查询时估计，营业、票务和预约仍需核实。

## 构建与验证

Windows 本机 JDK 的 AF_UNIX 管道初始化失败时，可仅对当前进程设置一个**不存在**的 `jdk.net.unixdomain.tmpdir`，按 [开发说明](development.md) 回退到 TCP。中文项目路径还会导致测试类加载失败，验证应使用相同源码的英文路径副本；不修改系统防火墙或全局 Java 设置。

```powershell
.\gradlew.bat --no-daemon '-Pmyplan.omitLegacyProviderKeys=true' testDebugUnitTest lintDebug assembleDebug
```

`myplan.omitLegacyProviderKeys=true` 让分享的 APK 不编入旧云语音／模型供应商密钥；新旅行能力仍使用电脑服务端。最终验证结果、APK 与 Git 提交以本轮交付说明为准。

本轮本机连接检查返回 200，原生 Cookie、攻略／AI／地图配置均可识别；新启动的 MCP 登录状态尚未恢复，需要使用电脑扫码工具重新登录。模拟器的硬件与软件启动均未达到可交互状态，未完成原生页面的截图和真机端到端验收，不能将编译／自动测试通过表述为手机实测通过。

最终自动验证：Android 全套 **263 项通过、0 失败**（含 11 项原生旅行测试、旧库迁移、15 节点保存与既有功能回归）；Node **211 项通过、0 失败**。Lint 完整运行通过，报告为 0 个错误、99 个警告；随后对容量边界调整重跑全套单测与 APK 构建并通过。分享的 APK 已核对两项旧供应商 BuildConfig Key 均为空。交付目录保留各次成功日志、APK SHA-256 与源码提交清单。
