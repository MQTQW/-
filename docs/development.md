# 开发说明

## 环境与构建

项目使用 JDK 17、Android SDK Platform 35、Build Tools 35.0.0、Gradle Wrapper 与 Kotlin。最低支持 Android 10（API 29），当前 compile / target SDK 为 35。具体依赖版本以 `gradle/libs.versions.toml` 和 `app/build.gradle.kts` 为准。

将仓库根目录的 `local.properties.example` 复制为 `local.properties`，填写本机 SDK 路径。Java 路径由 `JAVA_HOME` 或 Android Studio 的 Gradle JDK 指定，不在仓库中硬编码。

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

仓库提供 Windows Wrapper 脚本；macOS / Linux 可以执行 `java -classpath gradle/wrapper/gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain testDebugUnitTest lintDebug assembleDebug`，调用相同的 Wrapper。调试 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。

### AI 与系统语音配置

v1.0.6 首页与快速创建小窗使用「一句话安排」：文字与系统语音转写进入同一个 `PlanDraftWorkflow`，优先处理本地支持的简单表达；复杂理解通过用户配置的 AI 接口生成草稿，最终均需用户确认保存。系统语音通过 `RecognizerIntent` 调用手机识别服务，是否可用、支持的语言及是否联网由设备和该服务决定；缺失时可使用键盘语音输入或打字。

复杂 `parse` 和计划 `split` 使用 `server/ai-assist` 中的轻量 Node.js 服务。用户自行部署后，在「设置 → AI 计划助手」填写完整接口地址和专用访问码；模型供应商密钥仅配置在服务端。这轮提供 App 与接口源码，没有购买服务器、部署公网服务或使用真实模型密钥完成在线验证。接口、HTTPS、鉴权与限流说明见 [AI 服务说明](ai-service.md)，产品行为见 [一句话安排与计划拆解](ai-plan-assist.md)。

`voice/` 下的旧云语音类，以及 `local.properties` 的 `volc.api.key`、`deepseek.key` 和对应 BuildConfig 字段暂留兼容，首页新入口不再调用这套自建云 ASR / TTS 链路。两项旧密钥应留空；配置它们会写入 APK，不能用于正式分发。构建、本地解析、手动步骤、提醒、专注和回归测试无需真实模型密钥。

### Windows 环境排查

Windows JDK 17 在中文项目路径下可能无法加载 Gradle 测试类；遇到此问题可将相同源码复制到英文路径后执行测试。

若当前 Windows 环境的 AF_UNIX 不可用，可在当前终端为 JVM 指定一个不存在的 `jdk.net.unixdomain.tmpdir`，使其回退至 TCP；无需修改系统网络配置。该处理仅针对遇到相同错误的环境，不是构建的通用前置条件。

## 提醒与完成规则

- 一个计划可以包含多个提醒。重复计划的「完成今天」记录当天打卡，不取消后续日期的重复提醒；一次性计划完成后取消尚未触发的提醒，完成状态不随午夜重置。
- 计划开关负责暂停整个计划，各提醒的开关负责暂停单个时段。一次性计划按绝对时间调度，过期未完成事项不会重新安排到第二天。
- 手动保存、语音创建、通知栏快记、删除撤销和重启恢复共用提醒同步逻辑。保存采用 Room 事务，触发时重新检查计划和提醒是否存在、启用且版本有效。
- 一句话安排的文字和系统语音转写共用草稿流程；支持一次性日期、每天、工作日、自选星期、重复计划多时段及 15／25／45 分钟建议专注时长。草稿先经本地校验并展示，可修改后确认保存；离开入口取消尚未完成的解析，不让晚到结果覆盖当前输入。
- 完成记录按计划及本地日期唯一保存。重复完成不会增加打卡或积分；撤销后打卡回退。已消费奖励被撤销时会抵扣后续积分，避免反复完成刷取奖励。v1.0.5 的限时兑换按请求 ID 去重，同一应用有有效授权时不重复扣分或延期，过期后可发起新的兑换。
- 午夜执行日切，应用启动、回到前台和专注监控也会补做错过的日切。重启、应用更新、时间 / 时区改变及精确闹钟权限重新授予后恢复提醒。

声音播放、勿扰行为和后台冷启动诊断见 [闹铃播放与排查](alarm-audio.md)。通知栏输入、确认与一次性计划行为见 [通知栏快记](notification-quick-capture.md)。

桌面卡片、尺寸适配、直接完成 / 撤销及快速创建见 [桌面日常卡片](home-widget.md)。没有添加桌面卡片时，不启动小组件的 Room 数据订阅。

选择计划开始专注、确认完成、1 积分兑换单应用 10 分钟，以及暂停 / 重启 / 跨天规则见 [计划驱动专注与限时解锁](plan-focus.md)。这条流程在手机本地运行，沿用已有积分奖励，不需要账号或服务器。

步骤支持手动维护，也可在配置服务后请求 AI 建议。生成后先编辑、勾选并采纳，再保存计划；采纳本身不写入数据库，也不生成额外提醒。步骤勾选及步骤专注的确认只记录这一步，不标记父计划完成、不发积分；整计划仍需单独确认完成，沿用原奖励。

## 数据与升级

计划数据库提供 **v1→v2→v3→v4→v5→v6→v7→v8** 的保留数据迁移。v5 为每条提醒保存调度版本，编辑前已进入处理队列的旧事件会被忽略；v6 增加一次性计划的完整时间与唯一创建令牌；v7 新增当前专注会话与限时授权表；v8 为计划增加建议专注时长、新增有序步骤表，并在专注会话中保存可选目标步骤。迁移保留原有计划、提醒、打卡、完成历史、积分账本、专注会话和限时授权。旧版独立的单次 / 每天 / 每周提醒保留原规则，重新编辑提醒时采用当前计划级重复规则。

专注数据库 **v1→v2** 保留应用限制、任务和使用记录，并增加当天解锁状态。数据库不通过破坏性迁移清空用户数据。Room schema 位于 `app/schemas/`。

停用的专注规则继续显示，便于重新启用；规则更新和删除后，根据剩余有效规则重新计算锁定状态。无障碍服务订阅数据库锁状态，避免仅依赖广播和旧缓存。分类用量采集会带入应用规则中保存的分类，应用分类归属不被当作一条分类限额。

专注确认完成先取得共享 `PlanActions` 操作锁，再将计划完成、原有奖励与会话确认放入同一个 Room 事务；兑换扣分和授权写入也使用同库事务。每日限额仍保存在独立专注库，临时授权不改写原限额或旧的当天解锁标记。有效限制由当前限额、运行中的专注和未过期授权共同计算。

步骤通过外键关联计划，删除计划时级联删除；撤销删除使用计划、提醒和步骤快照共同恢复，保留步骤顺序、标识和完成状态。编辑步骤与计划、提醒在同一事务保存，保留已有稳定标识的完成状态；步骤勾选不修改父计划版本，也不会中断其他步骤的专注。循环计划只将当天的步骤完成状态视为有效，ONCE 步骤完成跨天保留。

本地日期由 `DateProvider` 发布，专注、日历、统计和积分随日期变化更新。专注倒计时使用可注入的 `FocusClock`，记录单调时钟锚点、开机次数及本地日期，区分同次开机内的进程重建与手机重启；读取剩余时间不逐秒写入数据库。测试可使用固定时钟，避免断言依赖实际执行日期。

「导出计划备份」通过系统文件选择器导出 JSON 格式 v3，包含全部计划、提醒、每日打卡统计、计划完成历史、一次性计划的完整时间点、建议专注时长及有序步骤和完成状态；不包含 AI 服务地址、访问码、模型密钥、录音或积分余额。当前尚无应用内导入界面。

AI 地址和访问码保存在独立的 `ai_assist_settings` SharedPreferences，系统云备份与设备迁移规则均将它排除。应用只在智能整理、拆解时发送本次内容及所需的标题、说明，不上传整个计划库。服务不接受修改本地计划或扣积分的命令，模型输出也不能直接触发这些操作。
