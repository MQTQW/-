## 3. 换一台 Windows 电脑继续运行

### 3.1 取代码与依赖

使用便携源码 ZIP 解压到可写目录，或从 GitHub 拉取 `codex/travel-planner`。用 `git rev-parse HEAD` 对照第 1 节提交；ZIP 的版本以随包清单为准。目录建议使用简短英文路径，例如 `C:\Work\MyPlan`，便于 Android 构建排错。

网页运行需要 Node.js 22+、当前版本 Chrome 和可用网络。Android 构建另需 JDK 17、Android SDK Platform 35、Build Tools 35.0.0；仓库已包含 Gradle 8.13 Wrapper，不需要全局 Gradle。

主 ZIP 与 GitHub 不含 `.env.local`、`local.properties`、小红书 Cookie、浏览器用户目录、GitHub 凭据或 API Key。新电脑使用自己的配置并重新扫码登录小红书，不复制旧电脑登录状态。便携运行时的启动方式、MCP 可执行文件、补丁和许可证以包内说明及文件清单为准。

### 3.2 配置本机真实服务

1. 按便携运行时说明启动本机小红书 MCP，并在新电脑重新完成登录。
2. 在仓库外建立 MCP 私有连接 JSON，结构为 `{"url":"http://127.0.0.1:<MCP端口>/","token":"<本机服务令牌>"}`。使用本机运行时分配的令牌。
3. 在本机服务端配置中填 `DEEPSEEK_API_KEY`，可选 `DEEPSEEK_MODEL`（默认 `deepseek-flash`）和 `AMAP_WEB_SERVICE_KEY`。默认配置位置是 `server/travel-research/.env.local`；可用 `--env-file` 指定其他本机文件。密钥不填进网页或 Android 的 BuildConfig。
4. 从仓库根目录构建并启动：

```powershell
node design/travel-live/build.mjs
node server/travel-live/serve.mjs --mcp-config "<本机私有JSON路径>"
```

打开 `http://127.0.0.1:8794`。前台启动用 Ctrl+C 停止；若使用便携后台启动器，按该启动器说明停止。关闭浏览器不会停止服务。修改 AI／地图配置后需要重启旅行服务；仅“重新检测”不会重新加载配置。

网页先确认攻略可检索、AI 可规划，再输入城市。地图未配置时保留未知坐标与待核对，不用假地图结果。遇到“未登录”先恢复 MCP 登录，再重新检测。

### 3.3 恢复与迁移的实际范围

- 浏览器清单、条件、行程、编辑副本与撤销存于当前来源的 localStorage，键为 `MY_PLAN_TRAVEL_LIVE_20261030`。换电脑、浏览器、主机名或端口不会自动带过去。
- 服务端任务、研究池和会话是约 4 小时的内存数据；重启清空。相同有效 Cookie 会话才能继续原任务。图片可因 LRU 淘汰或重启失效，旧图 URL 不可当作可迁移文件。
- 原机器导出的 JSON／TXT 可用于阅读和备份，目前没有导入恢复界面。新电脑复现真实链路应重新检索、选择和编排；脱敏证据 JSON 不是可恢复的服务器缓存。
- 页面“停止查看”只停止轮询，不取消服务器执行。任务中途改输入仍保留原任务快照，不把返回结果贴到新输入上。

## 4. Android 源码构建与边界

仓库已有 `gradlew.bat`、Wrapper JAR 和配置。从项目根目录把 `local.properties.example` 复制为本机 `local.properties`，将 `sdk.dir` 改成新电脑的 SDK 路径，例如 `C\:/Users/<用户>/AppData/Local/Android/Sdk`。不要沿用旧电脑绝对路径；示例里的旧 `volc.api.key`、`deepseek.key` 留空，不把服务端密钥编入 APK。通过 `JAVA_HOME` 或 Android Studio Gradle JDK 选择 JDK 17。

```powershell
Copy-Item -LiteralPath .\local.properties.example -Destination .\local.properties
```

修改 SDK 路径与留空旧密钥后，再执行构建：

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

APK 产物路径为 `app/build/outputs/apk/debug/app-debug.apk`；当前版本号本身不表明本次联网新功能已经进入 APK。

历史原生说明在 `docs/travel-planner.md`、`docs/development.md`：旅行使用独立 Room `travel.db`，原计划与旅行数据不能因接入新链路被清空。旧 `TravelAssistService.kt` 对接的是旧 AI 草稿契约，不能把它当成本轮 live 客户端直接复用。网页保存、API 任务和 Android Room 是三个不同的数据层。

| 路径 | 接手时先看什么 |
| --- | --- |

| `design/travel-live/live-client.js` | 同源会话、CSRF、请求、任务轮询和配图显示 |

| `server/travel-live/serve.mjs` | 页面与 API、会话、任务、研究池和输入指纹 |
| `server/travel-live/engine.mjs` | 三主题检索、来源校验、候选平衡截取、POI 与配图 |
| `server/travel-live/selection-planner.mjs` | 真实 AI 的已选项规划、结果校验、部分交通查询 |
| `server/travel-live/media.mjs` | 不透明图片代理、下载限制、LRU 36 项 |
| `server/travel-research/ai-provider.mjs` | 共享提取器；可选 `discoveryMode` 扩展美食／体验意向，默认保持原模式 |
| `app/src/main/java/com/example/myplan/travel/` | 现有原生旅行数据、操作、ViewModel 与 Compose 页面 |

| API | 契约 |
| --- | --- |
| `GET /api/session` | 取得 Cookie 会话、CSRF 和攻略／AI／地图能力；可用 `?refresh=1` 复查连接 |
| `POST /api/research` | `{destination,count:3}`，返回 `{jobId}` |
| `GET /api/jobs/<id>` | `running/done/failed`、实际进度和完成结果 |
| `POST /api/plan` | `{researchId,selected:[{id,priority}],form}`，返回 `{jobId}` |
| `GET /api/images/<id>` | 已登记图片字节，需有效本机会话；过期返回无图 |

POST 需要相同 Cookie、同源 Origin 与 `X-CSRF-Token`。规划结果为 `ready` 或 `needs_changes`；后者给出未排入的具名项目，不能伪装成功。字段、错误和恢复说明以 `server/travel-live/README.md` 为准。

8790–8793 是历史静态原型端口，不是当前真实服务。旧设计目录与历史截图保留用于对照，当前目标是 `design/travel-live` + `server/travel-live` 的 8794。当前只监听本机；没有公网部署、局域网共享或 Android 访问入口，手机上的 `127.0.0.1` 也不会指向这台电脑。

## 6. 继续开发必须保留的规则

每轮最多读 3 篇帖子、保留 12 个候选；综合攻略、本地美食、特色体验分别检索，候选在已有分类间轮流保留。没有来源支持就不造内容；0 个体验是有效结果。美食和体验是意向，不把菜名自动匹配成商家或为活动补坐标。地理类地点最多核对 8 个，`verified` 只表示名称／城市／坐标，不证明营业、价格、预约或引用说法全部真实。

攻略图可以是文字、拼图或介绍页，统一标“攻略配图，非地点实拍确认”，允许多候选共享一图。配图通过 `/api/images/`，不导出上游鉴权 URL。手动更换地点清除旧坐标、配图、核验和来源关联，不能保留“已验证”的外观。

首次 AI 只能安排本次已选候选；成功时每项出现一次，额外固定项只来自用户条件。必选与固定时间独立。容量不足明确回到选择／条件；手动补充项暂不支持首次远程编排，生成后可手动加。结果“规则调整”仍为本地“少走一点／晚出发”规则，要继续标清，不称作新的真实 AI。

交通估计带查询时间，未知路段留待核对；时间不足显示具体差额。编辑后使受影响的交通证据过期，TXT 与 JSON 不应丢掉这些提醒。天气当前只有准备提示，预算用户自填。

## 7. 下一位开发者的明确任务

1. **先定 Android 可访问的服务入口。** 当前 loopback 仅供本机网页，不直接改成无保护的局域网或公网服务；明确部署／鉴权和 Cookie／CSRF 适配后再接客户端。
2. **实现原生 live API 客户端。** 对应 session → research → job polling → plan → job polling；保留原任务输入快照、过期恢复、取消查看与错误状态。供应商 Key 继续只在服务端。
3. **按已确认交互做 Compose 页面。** 城市 → 三类真实候选／来源图 → 清单与必选 → 条件 → 概览／行程、列表／地图、编辑与撤销。继续使用 MY PLAN 暖白／sage 及既有深色；不把样例候选混入真实来源。
4. **建立 Android 数据映射与验收。** 明确采纳后何时写 Room，保留节点标识、来源、位置状态、交通查询时间和警告；生成／预览不自动创建提醒。增加已选项守卫、过期任务、无图、0 体验、时间不足和换地点证据清除的回归。
5. **做真实手机验收后再交 APK。** 检查触摸、软键盘、安全区、后台任务恢复、深浅色和旧数据升级。本次浏览器记录与旧 APK 不替代这些检查。

完成范围限定为交接、便携运行与工作分支推送；后续功能从上述任务继续，不把当前网页能力提前宣称为 Android 已上线。
