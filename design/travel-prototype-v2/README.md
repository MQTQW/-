# MY PLAN 行程交互原型 V2

可在浏览器中体验的本地行程原型，沿用上一版的暖白、鼠尾草绿与四张旅行照片。验收主线是「杭州三天，下午两点到，酒店已订，不要太赶」：创建草稿、核对餐馆、编辑中查出处、预览并应用 AI 变化、撤销与重开。

这是固定资料和本地规则演示，未连接真实 AI、小红书检索、地图、天气或 Android；生成过程也没有服务器或后台服务。

## 打开与开发

直接打开本目录的 [index.html](index.html) 即可体验。推荐通过固定本地地址访问，便于稳定复用浏览器草稿。在本目录运行：

```powershell
node build.mjs
node serve.mjs
```

打开 [http://127.0.0.1:8792](http://127.0.0.1:8792)。`serve.mjs` 只提供 `/` 和 `/index.html`，按 Ctrl+C 停止。

`build.mjs` 将样式、脚本、照片与署名嵌入单一 HTML，并校验脚本语法、生成脚本哈希 CSP；页面不加载外部字体或资源，`connect-src 'none'` 禁止在线服务请求。照片来源与许可链接可由用户主动打开。修改源文件后须重新构建，不直接修改生成的 HTML。

## 建议体验顺序

1. 从「先试试杭州三天」进入，识别条件，核对日期、14:00 抵达、酒店和返程时间；开始规划。也可选择杭州 1–5 天或「还没定日期」。
2. 在概览选择待定餐馆；确认页保留当天前后站点和攻略依据。候选和关键词搜索都是本地样例，仍可保留待定。
3. 进入行程列表，编辑一站的名称、时间、时长、备注和固定状态；查看 S1／S2 后返回，输入仍在。点「保存修改」才更新行程。
4. 切到第 2 天，选择「AI 调整这一天」→「少走一点」→生成变更预览。查看变化和保留项，应用后再撤销。
5. 在列表选一站并切换地图，或从地图回列表定位；再试添加、移除、跨天移动与明确指定新时间的顺序调整。
6. 修改预算后保存；勾选准备项立即保存。留下一处未完成编辑，刷新页面或用「模拟退出重开」返回首页后继续编辑。
7. 从行程工具导出 TXT 或 JSON。桌面两侧的预览控制在手机宽度下位于手机界面下方，向下滚动页面可找到。

## 已实现的操作规则

| 范围 | 当前行为 |
| --- | --- |
| 创建 | 仅杭州 1–5 天；日期可待定。到达、住宿、返程形成固定安排，首日可选游览不早于到达与入住之后；时间冲突会明确报错。 |
| 生成 | 四阶段延迟演示；页面仍打开时可返回首页或继续查看旧稿。新结果不会覆盖正在编辑的旧稿。刷新后进度暂停，需主动继续。 |
| 草稿 | 一份当前主行程；旧稿和在其他页面完成的新稿保留在「其他已保存的行程」，可切换，并保留各自行程、编辑副本和撤销历史。 |
| 逐站编辑 | 表单输入与已提交数据分开；查看出处后可继续。放弃修改或切换到另一站前有明确选择。名称编辑仅改显示文字；替换实际地点使用独立操作，并区分原攻略与新地点依据。 |
| 添加、移除、移动 | 手动新增不借用攻略或坐标；移动按明确开始时间排序，不自动顺延相邻安排。固定项须先主动解除固定才可移动或移除。跨午夜、无效时长与时间重叠均被拒绝。 |
| AI 调整 | 仅支持「少走一点」和「晚出发一小时」两类本地规则；前者移除一站可选游览，后者顺延可调整项一小时。范围为当天、当天剩余或整趟；「剩余」从当前选中站开始，不读取真实出行进度。 |
| 应用与撤销 | 预览不修改原稿；应用前验证行程版本与时间冲突，保留固定与手改项。模型也保护已有完成标记，当前界面未提供完成／跳过打卡。已提交修改保留最近 10 步撤销；放弃预览不改变行程。 |
| 列表与地图 | 同一天共享选中站点。地图按样例坐标展示分布，未知位置不标点；虚线仅连接相邻已知位置，不表示实际道路、距离或耗时。 |
| 辅助信息 | 预算编辑暂存，保存才生效；门票零元表示待核对。准备清单勾选即时提交，可撤销。天气页提供准备提示，没有实时预报或自动换景点。 |
| 导出 | TXT／JSON 只导出当前已提交行程，包括待定标记、来源、预算和准备状态；未提交编辑副本及其他行程不在导出内。当前没有导入功能。 |

## 本机保存与故障演示

localStorage 键为 `MY_PLAN_TRAVEL_V2_20261030`，内容仅属于当前浏览器与当前来源（协议、主机、端口）。例如 `127.0.0.1:8792`、`localhost:8792` 与直接打开文件不会共享同一份存储。`file:` 页面是否允许持久存储取决于浏览器策略。

表单、已提交行程、未完成站点编辑与本地规划进度会尝试保存；重开先回「我的行程」，可继续编辑或规划。保存失败时页面明确提示「内容仍在」，保留当前内存内容，并提供重试；此时重开只能读到最后成功保存的版本。导出当前已提交行程可另存备份。

预览控制的「部分资料失败」可演示重试或用已有 S1 资料形成草稿；「演示本机保存失败」只注入存储写入失败。它们不代表已经接入或验证真实服务故障。关闭页面后不会继续运行生成任务，也没有提醒通知。

## 验证与边界

```powershell
node --test model.test.mjs app-contract.test.mjs
```

2026-10-30 已通过 32 项模型与应用契约测试，覆盖时间校验、固定与手改保护、编辑和来源上下文、预览应用与撤销、草稿切换、生成完成、部分资料失败和存储恢复。

浏览器界面检查记录位于仓库的 `delivery/travel-prototype-v2-20261030/qa/`：21 张 JPEG 覆盖 320／390／800／1280 宽度档、深色、列表与地图、地点确认、编辑返回、AI 预览和保存失败，`export-example.json` 是实际下载的导出样本。文件名中的宽度是测试视口标签；JPEG 输出像素可能因浏览器截图机制与滚动条不同，例如部分 `390` 文件实际约 375 像素宽。这些记录不等同于真机验收；手机软键盘、触摸惯性与设备安全区仍待真实设备测试。

真实 POI 搜索与导航、预约营业核实、通知、实时天气、自动交通重算和完整旅行约束引擎尚未实现。节奏与交通偏好目前保存为输入信息；整体改日期或天数通过新建草稿体验，旧稿保留，不在原稿中自动重排。

## 文件与资料

| 文件 | 用途 |

| `model.js` / `model.test.mjs` | 本地资料、创建与编辑校验、变更方案、撤销与存储模型及其测试。 |

S1、S2 是内置的两份攻略资料样例，保留样例标题、作者、日期与安排关联；本轮没有重新检索或读取原帖，不表示营业、门票或路线已经核实。照片许可与攻略依据分别展示；亮点照片仅用于有对应主题的实际安排，相关配图不会冒充对应地点实拍。完整照片署名可在预览页下方展开查看，许可记录以 `credits.json` 为准。
