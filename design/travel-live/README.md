# MY PLAN · 联网旅行规划

第一阶段真实联调页面：输入城市，检索真实攻略，查看帖子中的景点、美食与体验，自行选择后，再让 AI 编排行程。沿用 MY PLAN 的暖白／鼠尾草绿、结果编辑和撤销体验，尚未接入 Android。

## 打开与开发

本页面必须由本机旅行服务提供。准备 Node.js 22、当前版本 Chrome、已登录的本机小红书 MCP 和服务端 AI 配置；完整配置与接口说明见[服务说明](../../server/travel-live/README.md)。

从项目根目录运行：

```powershell
node design/travel-live/build.mjs
node server/travel-live/serve.mjs --mcp-config "<本机私有JSON路径>"
```

访问 [联网旅行页面](http://127.0.0.1:8794)。保持使用同一主机与端口，便于继续本机草稿和任务。单独打开 `index.html` 只能加载界面，不能代替联网服务；旧静态原型的 8793 启动方式不适用于这里。

构建将当前 CSS 和 JavaScript 合成 HTML，生成脚本哈希 CSP；允许同源 API 和图片，不嵌入旧版样例照片。修改源文件后重新构建，勿直接改产物。服务端 API Key 与 MCP 令牌只由后端读取。

## 建议体验顺序

1. 查看“旅行服务已连接”，确认攻略可检索、AI 可规划。若提示未登录或未就绪，先处理本机上游服务，再点“重新检测”。
2. 新建行程并输入城市，点“搜索当地攻略”。页面显示服务端真实进度；此时只整理候选，不生成行程。
3. 在景点、美食、体验中挑选。分类数量来自本次结果，可能没有某类；筛选只作用于当前候选。打开详情看摘要、原帖作者、来源与配图，所有候选初始未选。
4. 加入想去／想吃／想体验清单，按需要标记必去／必吃／必体验，再补充 1–5 天、日期和可选的抵达／酒店／返程条件。必选表示内容保留，不锁定时间。
5. 点“让 AI 安排已选内容”。成功结果只包含已选候选，以及用户填写条件形成的固定安排。未排下时返回具名项目和原因，保留清单供调整；不会用固定样例替代失败结果。
6. 查看结果概览与行程，切换当天列表／地图。尤其核对交通提醒：地图估计耗时可能超过排定空档；待核对不等于可通行，也不代表已找到最优路线。
7. 试编辑、来源返回、手动补充地点、撤销和草稿切换。初次真实 AI 编排暂不支持手动补充的清单项；请先移出本次选择，生成后再在行程中手动添加。
8. 需要微调时使用“规则调整这一天”。这里是本地的“少走一点／晚出发一小时”规则，先预览再应用，不发起新 AI 请求。导出可读 TXT 或当前已提交行程 JSON。

手机宽度下，显示设置和联调记录放在手机界面下方。向下滚动外层页面可找到；手机内容与底部面板分别滚动。

## 来源、配图与地点

候选来自本次真实检索和 AI 提取，保留 `sourceIds`／`sourceRefs`；来源面板提供标题、作者、日期、摘要与小红书原帖入口。不是所有帖子都能提取出三类内容。

照片是原帖攻略图，可能是拼图、文字图或介绍页；统一注明“攻略配图，非地点实拍确认”，同一张图可能用于多个候选。点图可查看代理提供的原尺寸，加载失败时保留文字和来源。当前构建不使用目录中继承的 Commons 样例资产。

只有完成 POI 身份和坐标匹配的地点才标到示意地图；未匹配、歧义或未查询的地点保留待确认。名称与坐标匹配不等于营业、预约、票价或原帖描述已核实。手动替换实际地点会清除旧坐标、配图、核对结论和来源关联，可撤销恢复；仅编辑显示名称不等于更换实际地点。

联调记录分别显示来源数、候选数、服务校验可读取图数、AI 已读取图数和地图已匹配地点数，可导出元数据记录。图片可读取与 AI 读图是不同指标，均不证明图片是候选地点实拍。

## 保存、任务与导出

本版使用独立 localStorage 键 `MY_PLAN_TRAVEL_LIVE_20261030`，保留城市、选择、条件、已生成行程、编辑副本和最近 10 步撤销，不覆盖 V3。存储属于当前浏览器与来源；换端口、主机或浏览器不会共享。保存失败时内容留在内存，可重试或导出当前已提交行程；尚未提交的编辑不会混入导出。

检索和首次编排是服务端任务。离开页面或“停止查看”不取消服务端执行；在同一有效会话内可继续查看。任务开始时捕获当次城市、选择和条件；之后的输入单独保存，不能把旧任务结果当成新输入的结果。重新编排产生新草稿，旧稿仍保留。

服务端研究池、任务与会话为约 4 小时的进程内数据，重启会清空，图片也可能被淘汰。浏览器里可见的旧清单不保证还能直接提交；出现资料过期时重新检索。已生成草稿的文字仍可查看和编辑，失效图片提供占位说明。

TXT 包含当前交通提醒、查询时间、逐日安排、备注、原帖链接、预算和准备清单；JSON 包含当前已提交行程结构。联调记录导出只包含统计和来源／候选元数据。天气目前只有准备提示，预算由用户填写，没有实时预报、报价、通知或 Android 写入。

## 验证与文件分工

从项目根目录运行：

```powershell
node --test server/travel-live/test/*.test.mjs
node --test design/travel-live/model.test.mjs design/travel-live/live-client.test.mjs
```

脱敏真实检索记录见[联调元数据](../../delivery/travel-live-20261030/research-evidence.json)，浏览器截图和最终复查由同目录交付记录说明。测试与浏览器尺寸检查不等于手机软键盘、触摸惯性、设备安全区或 Android 原生验收。

| 文件 | 用途 |
| --- | --- |
| `live-client.js` | 同源会话、请求、任务轮询、来源链接与配图代理显示 |
| `discovery-model.js` | 本轮候选池、选择与首次编排校验，无固定候选回退 |
| `model.js` | 行程编辑、规则变更预览、撤销和本机保存 |
| `app.js` | 真实任务流程、快照核对、面板、交通证据失效与导出 |
| `discovery-views.js`、`create-views.js`、`result-views.js`、`ui.js` | 候选、条件、结果与共用控件 |
| 五份 CSS | 继承品牌、手机布局、联网状态与证据说明 |
| `build.mjs`、`index.html` | 同源联网前端的构建脚本与产物 |
| `PRODUCT.md`、`DESIGN.md` | 当前产品范围与实际视觉规范 |
