# MY PLAN 行程 AI 原型
<!-- impeccable:product-schema 1 -->

## Platform

web

## Purpose and users

供 MY PLAN 作者在开发前选择 Android 行程 AI 模块的交互方向。用户已明确先设计可点击原型，比较后再决定实现；个人自用验证，沿用已经认可的温暖轻巧 Android 视觉。

本轮只比较同一个行程规划模块的三种组织方式。判断重点是：需求是否容易表达、生成过程是否可理解、草稿是否容易核对和修改、来源是否容易追溯。

## Scope

| 方向 | 首要操作与结果组织 | 需要比较的取舍 |
| --- | --- | --- |
| 分步规划（选择器：分步） | 填目的地与偏好，确认地点，再按天查看时间线 | 步骤更多，但进度和下一步明确 |
| 对话共创（选择器：对话） | 从一句话开始，将调整请求与内嵌行程留在对话中 | 表达自然，长行程的浏览距离会增加 |
| 攻略先行（选择器：攻略） | 先阅读和选择来源，再确认地点，先看分布与每日路线 | 来源掌控更多，首次生成多一次选择 |

三方向均可完整点击：输入旅行需求 → 模拟检索 → 地点歧义确认或暂跳 → 按天草稿 → 节点编辑、来源查看、偏好调整 → 保存反馈。共用返回继续、手动安排和异常恢复。它们是同一模块的三种候选交互，不是三个新页面产品。

原型位于独立目录，只在浏览器内运行。用户选择前不整合到生产界面，不修改 Android 或已有后台；不调用真实检索、地图或模型，不写入 App，也不创建提醒。

## Evidence and demo data

演示目的地固定为杭州，默认 3 天、2026-11-07 出发、舒缓节奏、公共交通。日期输入下限固定为本轮演示日期 2026-10-28，不是实时日历能力。目的地或对话改为其他城市时，会提示改用杭州示例。

来源样例是此前已取得的两篇攻略标题、摘要与地点：S1「本J人耗时6h做的杭州攻略，满意的睡不着」；S2「杭州3天2夜懒人攻略｜西湖、灵隐、九溪路线」。原型只演示出处关联，不嵌入真实图片或完整原文。几何地点分布和虚线连接是示意，不代表道路或导航。

检索进度、交通估计、任务返回继续、登录恢复、对话调整和保存均为交互模拟。对话调整使用本地规则，不能据此判断真实模型的理解或规划能力。营业、门票、预约和交通信息仍需另行核实。

用户输入与保存标记只在当前内存中。切换方向、重置或刷新后重新开始；URL 的 `v` 参数只保留方向。原型不读取 API Key、Cookie 或私密配置，不使用持久存储。页面外壳始终标明演示性质，自包含 HTML 的 CSP 禁止服务连接。

## Implemented behavior

- 地点确认会实际改变草稿中的节点；未确认项可暂留备选，明确跳过的地点不加入安排。
- 修改节点保留出处，时间冲突或跨午夜会阻止提交；可使用示例空闲时段修复，再保存。手动新增节点没有虚构来源。
- 天数和出行方式更新保留手动修改；受影响的交通估计清为待更新。
- 攻略先行至少选择一篇来源才能继续；只选一篇时，地点、匹配项和引用受该来源限制。
- 检索超时可重试或使用已取得资料；来源登录失效可模拟更新后继续；无结果可修改需求或手动安排。离开进度页可回到主页继续当前模拟任务。
- 保存前检查空行程和时间冲突；保存完成页仅反馈内存状态，不代表生成后台任务、写入 App 或自动创建提醒。

## Confirmed constraints

视觉继承 `app/src/main/java/com/example/myplan/ui/theme/Color.kt`；具体颜色、字体和组件值记录在 [DESIGN.md](DESIGN.md)，不另立品牌。卡片、按钮与输入保持既有圆角语言。

中文清晰具体，不使用此前被否定的「今天轻轻开始」文案。不使用 Pencil。Prototype Picker 的 CSS、JS 和键盘行为按会话使用的 prototype skill 原样保留，使用允许的顶部位置避开底部主操作，标签为「分步 / 对话 / 攻略」，全名与取舍放在手机界面外说明。

本轮交付是供选择的隔离原型。完成浏览器正常路径与列明异常检查，不等同于真实后台验收或 Android 联调；选择后另行确定生产实现。
