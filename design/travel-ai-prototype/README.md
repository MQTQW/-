# 行程 AI 交互原型

MY PLAN 同一行程规划模块的三种候选交互：分步规划、对话共创、攻略先行。视觉沿用已确认的暖白 sage/cream Android 系统。原型独立于 Android 和后台；服务连接禁用，保存只产生内存反馈。用户选择前不整合到生产界面。

## 预览与文件

从项目根目录运行：

```powershell
node design/travel-ai-prototype/build.mjs
node design/travel-ai-prototype/serve.mjs
```

默认打开 [本机原型](http://127.0.0.1:8790)。构建后的 [index.html](index.html) 自包含，也可直接打开；没有外部库、字体或图片请求。构建会同步语法检查脚本并写入内联脚本的 CSP 哈希；`connect-src 'none'` 禁止服务连接。预览服务器只绑定本机 `127.0.0.1:8790`，只提供根页面和 `index.html`。

| 文件 | 用途 |
| --- | --- |
| [PRODUCT.md](PRODUCT.md) | 比较目标、三方向、演示数据与实现边界 |
| [DESIGN.md](DESIGN.md) | 从既有 App 与原型提取的颜色、字体、布局和组件记录 |

## 切换方向

顶部标签是双字简称，完整名称与取舍在手机界面外说明：

- [分步：分步规划](http://127.0.0.1:8790/?v=1)——表单、明确顺序、时间线优先。
- [对话：对话共创](http://127.0.0.1:8790/?v=2)——一句话输入、持续调整、内嵌草稿。
- [攻略：攻略先行](http://127.0.0.1:8790/?v=3)——先选来源、再处理地点，分布优先。

键盘 `1`–`3` 或左右方向键切换，`R` 重置当前方向。在输入框、文本域、选择器中输入时不响应这些快捷键。URL 的 `v` 只保留方向；切换、重置或刷新会清空当前内存流程。

桌面左侧是页面目录，右侧是方向说明与异常选择；窄屏时它们排在手机下方，可以向下滚动到达。目录可快速进入示例状态，可能准备示例草稿；完整流程体验请从输入页开始。窄屏从目录跳页后会回到手机顶部。

## 建议体验顺序

先在每个方向完整体验一次正常流程，再比较输入成本、结果核对与修改方式。

1. **分步规划**：保留杭州示例，展开出行偏好 → 开始规划 → 可先返回，再从主页继续 → 确认具体地点，或暂跳看已匹配地点 → 按天查看和编辑节点 → 展开攻略依据、分布，查看来源后返回 → 保存这份行程。
2. **对话共创**：输入杭州需求或使用建议 → 生成行程草稿 → 确认地点 → 查看对话内的每日行程 → 点击「少走一点路」或输入调整并提交；节点数或停留时长实际改变 → 继续节点编辑、查看来源 → 保存。对话采用固定演示规则，不是真实模型响应。
3. **攻略先行**：先找旅行攻略 → 先挑选参考攻略，查看摘要后返回 → 至少选择一篇再继续整理 → 确认地点 → 先看地点分布和每天路线，再查看每日时间线 → 调整、核对出处 → 保存。可以取消全部来源验证阻挡；只选一篇时，后续地点与引用受该篇限制。

共用操作还可验证：修改节点到重叠时间时禁止提交，再用空闲时段修复；修改天数或出行方式后手动编辑保留、旧交通估计清除；从空白行程手动新增节点后保存，确认没有虚构来源。

## 异常演示与边界

在工作台选择「检索超时 / 来源登录失效 / 没有找到攻略」，再开始规划；也可用目录的「检索异常恢复」快速查看。重试会回到正常演示。

| 场景 | 可尝试的恢复 |
| --- | --- |
| 检索超时 | 重试、使用已取得的攻略、先手动安排 |
| 来源登录失效 | 模拟更新来源连接后继续、返回修改、手动安排 |
| 没有找到攻略 | 修改需求重试或手动新增安排 |

杭州为固定数据集，默认 3 天、2026-11-07 出发；日期下限固定为 2026-10-28。检索、交通、登录恢复、页面内返回继续与保存均为模拟。离开进度页继续只发生在本页面生命周期内，不具备后台任务或刷新后恢复能力。来源只展示已有摘要，地点分布是几何示意，不能导航。保存不会写入 Android，也不会自动创建提醒。
