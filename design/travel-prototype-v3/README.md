# MY PLAN 先选内容，再编排行程 · V3

可独立打开的本地交互原型。主线是「输入城市 → 看攻略里的具体内容 → 自己选择景点、美食与体验 → 补充出行条件 → 只编排已选项」。沿用前版的暖白、鼠尾草绿、编辑和撤销体验。

当前仅支持杭州 1–5 天，使用固定资料与本地规则。未连接真实 AI、MCP、小红书检索、地图、天气、提醒服务或 Android，也没有服务器规划任务。

## 打开与开发

直接打开本目录的 [index.html](index.html)，或在本目录运行：

```powershell
node build.mjs
node serve.mjs
```

访问 [http://127.0.0.1:8793](http://127.0.0.1:8793)。服务仅提供 `/` 和 `/index.html`，按 Ctrl+C 停止。推荐固定使用同一地址，便于复用本机草稿。

`build.mjs` 把样式、脚本、照片和许可记录嵌入单一 HTML，校验脚本语法并生成脚本哈希 CSP。页面不加载外部字体或资源，`connect-src 'none'` 禁止在线服务请求；署名中的外部许可链接可由用户主动打开。修改源文件后重新构建，不直接编辑生成的 HTML。

## 建议体验顺序

1. 点「新建行程」或「先看看杭州攻略」，输入杭州并整理攻略样例。这个阶段只准备候选，不生成行程。
2. 在景点、美食、体验间切换，查看详情和 S1／S2 依据；可用关键词筛选本地候选。所有项目初始均未选择。
3. 加入想去清单，按需要标记「必去／必吃／必体验」，也可手动补充名称、分类和时长。零选择时不能进入编排条件。
4. 选好后再补充条件。新建默认 3 天、「还没定日期」，到达、酒店、返程均留空；支持 1–5 天，已确定的安排可展开填写。
5. 点「用已选内容安排行程」。核对结果只包含已选内容及自己填写条件生成的固定安排；没选的景点不会自动加入。若时间不足，页面列出排不下的项目，保留全部选择供调整后重试。
6. 在结果中试逐站编辑、查看出处后返回、地点确认、列表／地图联动，以及 AI 变更预览、应用与撤销。查看原清单并重新编排会新建草稿，旧稿保留。
7. 留下一处未完成编辑后刷新或「模拟退出重开」，再从首页继续；也可切换「其他已保存的行程」、导出当前已提交行程的 TXT／JSON。

桌面预览控制和照片署名在手机宽度下排到手机界面下方，可向下滚动整个页面找到。

## 候选、来源与照片

内置 8 张固定候选卡；手动补充的项目另计。

| 分类 | 固定候选 |
| --- | --- |
| 景点（5） | 雷峰塔、灵隐寺、拱宸桥、断桥残雪、九溪烟树 |
| 美食（1） | 油爆虾：菜品意向，餐馆与分店待选 |
| 体验（2） | 运河慢走；喝茶与休息 |

S1 是图片攻略样例，S2 是正文路线样例，保留已有标题、作者、日期和简短参考内容。本轮未重新读取原帖，未抓取完整正文；界面的整理进度、来源正文和搜索结果均为固定演示资料，不代表实时检索、营业、门票或路线核验。

「喝茶与休息」明确标为原型作者的补充灵感，不附会帖子出处。手动添加同样不借用来源、照片或坐标。运河慢走、茶歇和其他体验的具体地点可手动记下；保存后仍无坐标，不会用无关景点替代体验。美食先保留想吃的菜，结果页只提供本地门店样例供主动选择，地址和营业仍待实际核对。

候选和结果亮点中只有雷峰塔、灵隐寺、拱宸桥使用对应主题照片；断桥、九溪没有匹配照片，保持文字呈现。另有一张西湖全景用于首页草稿封面，不冒充断桥实拍。四张 Wikimedia Commons 照片及原始署名、许可保留在 `credits.json` 和页面署名区，原文件未改动，仅以 CSS 裁切。

## 编排与编辑规则

| 范围 | 当前行为 |
| --- | --- |
| 选择与编排 | 生成时保存已选 ID、优先级和条件的副本；之后修改清单不会改变本次生成。结果不继承前版默认游览点，只保留已选内容与用户条件生成的到达／住宿／返程固定安排。 |
| 必选与固定 | `mustKeep` 表示保留内容，与固定时间 `locked` 独立。AI「少走一点」不删除必选项；必选不自动锁住时段。用户仍可主动编辑或移除。固定时间项须先主动解除固定，才能移动或移除。 |
| 区域与时段 | 按西湖、灵隐／九溪、运河等区域偏好和可用时段排布；餐饮尝试午间／傍晚时段，站点间留示例空档。到达和入住之后才安排首日游览，返程前预留空档；入住时间也是演示规则。没有计算真实路线、距离或交通耗时。 |
| 容量不足 | 返回失败与具名的未排入项目，不给出缺项的成功行程；全部选择及旧稿保留，可增加天数、改时间或自行减项后重试。 |
| 地点 | 已知坐标是样例；未知位置不标点。确认门店后，首页和行程的待确认状态同步更新。名称编辑只改显示文字，更换地点使用独立操作。体验仅手动记录地点文字，继续保留原体验与来源；实际位置和相邻交通待核对。 |
| 编辑与撤销 | 输入副本与已提交行程分开；查来源后返回保留输入，切换编辑对象前可选择继续或放弃。手动新增不补造来源或坐标。提交、移除、移动、预算和准备清单保留最近 10 步撤销；跨午夜、无效时长与时间重叠会报错。 |
| AI 调整 | 仅「少走一点」和「晚出发一小时」两种本地规则。范围为当天、当天剩余或整趟；「剩余」从当前选中站开始，不读取真实出行进度。预览不改原稿，应用前校验版本和时间，并保护固定、手改与已有完成状态。界面未提供完成／跳过打卡。 |
| 列表与地图 | 当天共享选中站；地图只示意样例坐标分布。未知位置仍保留在列表中，虚线只连接相邻已知位置，不表示道路或导航。 |
| 保存的行程 | 一份当前主行程；旧稿和在其他页面完成的新稿进入「其他已保存的行程」，可切换并保留各自编辑副本和撤销历史。重新编排不覆盖正在编辑的旧稿。 |
| 辅助与导出 | 预算是可编辑样例，门票零元表示待核对；准备项即时保存。天气仅有准备提示。TXT／JSON 导出当前已提交行程，不包含未提交编辑或其他草稿；没有导入功能。 |

节奏与交通偏好保存为输入信息，尚未驱动完整约束求解。日期、天数的整体变化通过重新编排新草稿体验。

## 本机保存与中断

V3 使用独立 localStorage 键 `MY_PLAN_TRAVEL_V3_20261030`，不读取或覆盖 V2 的键。城市、清单、条件、行程、未提交编辑和流程进度会尝试保存在当前浏览器、当前来源（协议／主机／端口）；`127.0.0.1:8793`、`localhost:8793` 和直接打开文件不共享同一份存储，`file:` 持久化取决于浏览器策略。

资料整理和编排只靠页面计时器推进；页面运行时可返回首页或看旧稿，关闭页面后不继续。刷新或模拟重开后回首页，运行中的进度转为暂停；资料需主动重新整理，编排需主动继续。预览控制的「模拟流程中断」保留已有选择与条件，需手动重试，不会用不完整选择生成草稿。没有后台续跑或提醒通知。

「演示本机保存失败」只注入写入失败：页面提示「内容仍在」，内存内容保留并可重试；此时重开只能读取最后成功保存的版本。可导出当前已提交行程另存备份。这些控制不代表真实服务故障已经联调。
