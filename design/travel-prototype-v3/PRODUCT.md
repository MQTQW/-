# MY PLAN 先选内容，再编排行程 · V3
<!-- impeccable:product-schema 1 -->

## Platform
web

## Purpose
用户先输入城市，查看攻略中的景点、美食与体验，自己选择并标记必选，再补充出行条件让AI编排。用户决定旅行内容，AI负责检索整理与后续编排；本轮用固定资料和规则验证这条交互主线。

## Scope
Operate 模式。沿用暖白／鼠尾草绿。城市发现 → 景点／美食／体验候选 → 我的想去清单 → 出行条件 → 只编排已选项。默认无预选内容，不猜酒店、到达时间或餐馆。必选代表保留内容，不固定时间；容量不足时保留清单并报出未排入项。食物是菜品意向，门店稍后确认。手动内容与作者补充灵感不附会攻略出处。保留V2结果浏览、编辑、地图、撤销和本机保存，旧版不修改。

## Boundaries
本地流程和规则演示，未接入真实AI、小红书、地图、天气或Android。候选来自两份已有资料样例及明确标注的补充灵感，不声称本轮实时检索。编排按区域和时段规则，不计算真实交通。进度仅在网页运行时推进，刷新后可继续本地演示，不承诺后台服务续跑。localStorage使用V3独立键，不读取或覆盖V2草稿；离线HTML存储取决于浏览器策略。正式通知、导航、真实检索及天气联调留待下一阶段。

## Visual authority
继承 design/travel-result-mobile 的品牌、照片与token。父目录原型保持不变。新版本先验证一致的操作规则，不另起品牌、创建三套候选或修改正式App。
