# MY PLAN 行程规划交互方案 V2

日期：2026-10-30。状态：供讨论的方案，尚未实施。

本次只读审查行程规划模块，包括 `design/travel-ai-prototype` 的三种创建候选，以及 `design/travel-result-mobile` 的旅行详情原型。未修改现有界面、Android 或服务端。依据为源码、原型文档和代表性浏览器走查；以下使用场景属于推演，尚未通过真实用户访谈验证。

## 1. 建议采用的主线

保留已认可的暖白、鼠尾草绿和图文景点卡片，把交互串成：

**表达需求 → 确认关键条件 → 生成并保留草稿 → 查看整体方案 → 就地核对与调整 → 准备出发 → 途中使用。**

创建采用“一句话需求＋可展开条件”的单一入口；选择攻略是可选步骤；AI 对话用于调整已经可见的行程。结果采用“概览／行程”两个主分区，行程内部切换“列表／地图”。预算、天气、出处保留直接入口。有效修改自动保存到本机；AI 改动先预览再应用，默认保护手动修改。

### 为什么调整上一版四标签

每日列表和地图实际在处理同一天、同一批地点。把它们合并到“行程”，日期和选中地点只维护一份，用户不用在两个页面反复找上下文。“更多”承担菜单作用即可，无须成为主要目的地。图文概览继续保留，不牺牲用户喜欢的展示方式。

## 2. 当前交互全清单

### 2.1 创建原型：三个候选，不是三个并存产品入口

| 当前候选 | 当前可执行的路径 | 需要保留的价值 |
| --- | --- | --- |
| 分步规划 | 输入目的地 → 展开日期、天数、节奏、交通、兴趣 → 开始规划 → 进度 → 地点确认或暂跳 → 每日草稿 → 修改与保存 | 条件清楚，下一步明确 |
| 对话共创 | 输入一句话或点示例 → 修改偏好 → 生成 → 确认 → 对话内草稿 → 输入或点“少走一点路／多休息” → 调整当前天 → 保存 | 自然表达与局部调整 |
| 攻略先行 | 输入条件 → 找攻略 → 阅读摘要、选择来源 → 至少选一篇 → 整理 → 确认地点 → 分布／时间线 → 修改与保存 | 用户能控制参考材料 |

### 2.3 工作台与演示边界

工作台跳页、主题切换、远期／近期天气选择、三候选选择器、异常场景开关、重置、署名折叠区和许可外链，用于设计评审，不应作为正式行程产品功能计数。

固定杭州候选、示意地图、模拟生成、页面内存保存、没有真实服务连接，是已经声明的演示边界。它们本身不计作程序缺陷；但后续实现必须补齐持久化、服务状态与失败恢复的交互规则。

## 3. 当前最影响真实使用的问题

| 优先级 | 发现 | 用户实际会遇到的结果 | 建议规则 |
| --- | --- | --- | --- |
| P0 | 创建与结果分离，前置确认规则也不同 | 不清楚应该先确认地点，还是先看草稿；暂跳后的地点容易脱离安排 | 合成一条创建流程；先看草稿；待定项留在当天占位 |
| P0 | 编辑中查看攻略不能回到原面板 | 输入了一半备注，查完依据后丢失编辑入口；再次编辑覆盖未提交副本 | 保留面板、输入草稿、滚动、选中日期；返回原位继续 |
| P0 | 修改的提交规则不同 | 预算返回即生效，编辑需保存，登塔又直接生效；容易误判是否已修改 | 表单先存副本、明确“保存修改”；勾选类即时生效；已提交内容自动持久保存 |
| P0 | 旧对话调整直接修改当前天 | “少走一点”会删站并重排，可能覆盖手改；没有撤回 | 展示变更与影响 → 应用／放弃 → 撤销；默认保护手改与固定安排 |
| P1 | 编辑能力不完整 | 想删除一站、移到明天、换一家店，却只能改几个文字／时间字段 | 增加新增、移除、换天、排序、替换地点；不把改名字当替换位置 |
| P1 | 全局“编辑／完成”缺少实质区别 | 用户以为进入了编辑模式，实际逐站按钮始终能点 | 去掉模式开关；站点就地编辑；排序用明确入口 |
| P1 | 同一门店从不同入口打开选择不同 | 可能带出上次未提交候选；已选门店“查看选择”反而清空勾选 | 每个节点绑定当前已选位置；区分查看、更换、本次未提交候选 |
| P1 | 跨来源、地图、每日的返回路径断开 | 查出处→看相关地点→看安排，返回却进旅行列表 | 上下文跳转保留阅读路径；主分区切换与页面返回分开 |
| P1 | 改备注也清空当天全部交通 | 简单修改影响了无关内容；用户不知道该重查哪段 | 按字段和相邻站更新；指出实际受影响范围 |
| P1 | 只有修改安排名称，缺少替换实际地点入口 | 用户可能把改名称误当成换地点，原位置和出处仍保留 | “改显示名称／备注”和“替换地点”使用两个动作；后者重新匹配位置和证据 |
| P1 | 准备清单、活动与保存／导出范围不一致 | 不知道哪些勾选已保存、换设备或导出后是否保留 | 统一保存范围与状态；导出说明包含及省略内容 |

代表性浏览器复核：从“断桥残雪”编辑中输入临时备注 → 点 S2 出处 → 返回。实际返回到每日列表，编辑面板未恢复。临时审查状态已还原，未改原型源码。

## 4. 真实场景应有的交互

| 场景假设 | 用户想完成的事 | V2 的完整回应与恢复 |
| --- | --- | --- |
| 只知道去杭州，时间未定 | 先判断三天怎么玩 | 只填目的地和天数即可规划；日期选“暂未确定”；用第几天和弹性时段；补日期后核对开放时间、预约和天气，保留已选地点 |
| 已订车票和酒店 | 不能打乱已确定安排 | 可补充到达／返程／住宿及固定时间；下午到达只排半天；酒店选择准确分店；排不下就提出删减或换天，不移动固定车票时间 |
| 手里有收藏攻略和必去地点 | 让自己的资料影响结果 | 可选添加链接、文字、手输地点；地点标“必须保留”；无法读取的原帖保留输入并说明状态，可补文字或继续，不伪装已读 |
| 只有几分钟，生成很慢 | 不一直盯着等待页 | 显示真实阶段和已完成数量；已有内容形成可看草稿；离开可继续；失败保留成果、只重试失败部分；手改后到达的新结果作为建议 |
| 午餐只知道品牌，不知道分店 | 不要被系统逼着猜 | 当天保留“午餐·门店待定”；点开看原文依据、地址候选、前后站和路线影响；使用／重新搜索／保留待定／移除；换入口不丢当前选择 |
| 想删一站、加咖啡店、把寺庙移到第二天 | 少操作地调整安排 | 站点菜单提供移除、添加、移至某天／某位置；排序有显式入口；预览时间和路段影响；完成后提供撤销；有冲突则展示可选修复 |
| 改到一半，想查一下攻略 | 查完继续手上的事 | 来源展示作为临时查看层或可恢复的子页；关闭后回原编辑面板，文字、光标、滚动和日期均保留；主动取消才丢弃副本 |
| 临时下雨或晚起 | 今天剩下的安排更合适 | 当天“AI调整”默认作用于剩余安排；保留完成项、返程、预约和手改固定项；先展示变化再应用；失败保留旧版；可撤销 |
| 已经出发且网络不好 | 随时看下一站和地址 | 已保存的行程、地址、备注可离线读；显示内容更新时间；当天进入行程优先选今日与下一站；点击才打开地图应用，不用预先申请持续定位 |
| 想借助 MY PLAN 到点提醒 | 确实提醒该提醒的事情 | 从具体站点或出发前检查中选择提醒；展示日期、时间、提前量并确认；未定日期先补齐；拒绝通知权限仍可看行程；改时间同步原提醒，避免重复 |

## 5. 页面与信息层级

### 我的行程

- 空态只给“创建行程”，附一条简短示例；已有行程显示最近草稿与出行日期。
- 生成任务以任务卡保留：进行中、部分完成、失败可继续、已完成。关闭进度页不等于取消任务；取消有独立动作。
- 已生成草稿自动归入我的行程，能再次打开；本地保存失败必须明确提示并提供重试。

### 创建页：一句话＋条件卡

主输入例如“杭州三天，带爸妈，下午到，不要太赶”。下方立即显示解析出的目的地、日期或天数、节奏和交通，允许点开修改。

生成前只处理会让整趟规划错误的缺项／冲突，例如城市不明确、天数矛盾。日期可以未定。酒店、到达、返程、必去、预算与参考资料为可展开项，不要求每个人填满。

“开始规划”之前概括本次任务条件；相同请求运行时可继续已有任务，避免重复提交。

### 生成页：有结果可先看

显示真实阶段，例如“正在整理攻略”“已匹配 8 处地点，2 处待确认”。阶段尚未完成时不展示假的完成百分比。已有结果可进入草稿；新增研究成果不自动覆盖用户已修改内容。

来源连接失效时保留任务，提供已有材料继续、稍后恢复或手动安排。个人自用阶段可以保留电脑端连接恢复说明；普通创建页不要求填写 Key。任务恢复能力未完成前，不能承诺“退出后继续”。

### 详情：概览／行程

| 位置 | 内容 | 主要动作 |
| --- | --- | --- |
| 顶部 | 行程名、日期或未定日期、本机保存状态；返回和菜单 | 修改基础条件；菜单含导出、归档等低频动作 |
| 概览 | 核心条件、待处理摘要、图文亮点、每日速览、预算／天气摘要 | 看是否适合；直达当天或具体待处理项 |
| 行程顶部 | 日期选择；列表／地图切换 | 切换显示方式时保持同一天、同一地点和各自位置 |
| 列表 | 站点、时间、停留、相邻交通、待核对状态、当天添加入口 | 查看站点；编辑／替换／移除／换天；调整顺序 |
| 地图 | 同一日路线、具体地点、选中点简卡 | 选择点；回列表定位；有确定位置时启动导航 |
| 当天工具 | 当天强度、可用空档、AI调整入口 | 只改今天／剩余安排；应用前看变更 |

预算与天气同时从概览摘要进入；准备清单从天气／出发前检查进入；攻略依据从站点进入，也能在菜单集中查看。“地点与攻略关联”保留为解释工具，首版不要求用户理解知识图谱。

图文亮点介绍回答“为什么值得去、为何放在这一天”；安排备注独立。照片卡、列表、地图和来源中的同一地点，统一打开同一份站点详情。路线片段卡明确标为路线，进入对应日，避免被误当成独立景点。

### 统一的站点详情

展示名称与具体地址、安排日期／时间、预计停留、推荐理由、相关依据、预约／营业核对状态。提供地图、编辑和站点菜单。缺位置时主要动作是“选择具体地点”，不显示可用导航。

景区与内部活动在核实关系后合成一站；是否登塔等是活动选项，不把同站父子地点变成必须二选一的地图记录。

## 6. 全局交互规则

### 保存、返回与关闭

1. 生成草稿和已提交修改自动写入本机，状态分别显示“保存中／已保存到本机／保存失败”。不会把当前内存状态称作已持久保存。
2. 安排编辑、预算编辑、具体地点更换先产生表单副本，点“保存修改／使用此地点”才提交；取消不改变原内容。查出处、暂离后能恢复副本。
3. 准备清单等简单勾选即时提交并自动保存；避免每次勾选都弹成功面板。
4. 系统返回先处理当前层：关闭查看层 → 返回原编辑面板／上页 → 返回行程列表。主动丢弃有改动的表单才提示保留或放弃；普通浏览返回不反复确认。
5. 移除、移动、应用 AI 建议等可恢复操作提供“撤销”。实际影响范围明确，不用一个全局“编辑／完成”开关包办全部任务。
6. 常驻“保存草稿”退出主操作位置。尚待处理时显示相应入口；查看时可不放强制底部主按钮；出发前和途中使用相应任务入口。

### AI 调整

`明确范围 → 表达意图 → 生成建议 → 比较变化 → 应用／放弃 → 自动保存 → 可撤销`。

- 范围明确显示“今天剩余／这一天／整趟”，不让一句“少走一点”默默影响全程。
- 默认保留完成项、预约／车票等固定项、用户手改的字段；不得私自丢弃必去地点。
- 变更预览具体列出新增、移除、换天、时间变化、待更新路段，以及哪些约束无法满足。
- 用户编辑期间到达的旧建议不能直接应用到新内容；提示重新计算受影响部分。
- 应用失败保留当前版本；不明确的要求先问与任务直接相关的问题，不连续追问所有偏好。

### 核对与冲突

- 分开记录“地址已匹配”“分店待选”“营业待核对”“费用估算”“交通待更新”。用户选过地点不代表营业和路线已核实。
- 待定项可以保存；仅对依赖未知信息的动作设限制，例如无坐标不能导航、无日期不能创建定时提醒。
- 时间重叠时指出具体两项；给出“调整此站”“顺延后续”“移到另一天／移除可选项”等适用选项。用户可取消修改，不能悄悄移动固定预约。
- 交通使用当前出行方式、实际可得的路线结果与合理缓冲；数据不可得时明确未知，不用直线距离伪装可走路线。

### 修改影响范围

| 修改 | 应更新的内容 | 应保留的内容 |
| --- | --- | --- |
| 备注／显示名 | 文字与保存状态 | 位置、路线、时间和原有证据 |
| 替换实际地点／具体分店 | 地点匹配、相关证据标注、前后路段及可行性 | 原来的用户备注、固定约束；旧地点仍可撤销恢复 |
| 开始时间／停留 | 时间冲突、相邻衔接、必要的后续建议 | 不相关日期和无关路段；固定项不自动移动 |
| 跨天移动／排序 | 原日和目标日的相邻路段、冲突、强度 | 无关天内容、手改与出处 |
| 日期、天数、酒店、交通方式 | 显示受影响日／路段和约束，确认后应用 | 不能因缩短天数就悄悄把安排全部塞进最后一天 |
| 活动选项 | 活动内容和建议时长；自定义时长如需变化先说明 | 用户已确认的时间约束 |

### 来源、天气、预算与导出

- 依据显示对应地点的片段、作者、时间和可打开的原文入口；原文不可访问时说明，保留摘录与已经取得的证据。网页／帖子的取得状态和事实核对状态分开。
- 预算明确整趟／每人、预计／实际。初版以整趟预计预算为主；未知门票显示“待核对”，不以 0 元暗示免费。
- 天气只在日期和有效预报范围具备时显示逐日预报，附更新时间；日期未定或过远时给准备建议。天气失败不阻断看行程。
- 导出优先提供普通用户可读清单；JSON 降为高级入口。导出当前已提交版本，保留日期、地点、时间、出处和待定标记；说明不包含的内容。
- 保存和导出的数据范围一致，包含确认后的活动选项与准备清单；尚未提交的表单先提示保存修改或导出原版。

### 途中与提醒

已确定日期的行程在出行期间默认定位今日，突出下一站、具体地址、导航和预约备注；仍可切回概览与其他日期。完成／跳过由用户操作，不以进入地图推断到访。

创建提醒按站点选择，不默认给所有节点响铃。展示具体触发时间及提前量，改期后更新同一提醒。通知权限在用户创建提醒时说明和请求；拒绝不阻断离线看行程。计划状态、提醒是否启用和来源是否核实分别呈现。

只有修改提交或 AI 建议应用成功后，才同步本行程关联的未来提醒；预览和取消编辑不改变提醒。替换地点时更新关联文案与地址，改期更新触发时间；移除／跳过站点或取消行程时，取消对应尚未触发的提醒。撤销同时恢复关联状态，已经触发过的提醒不因撤销而重复响铃。

## 7. 必须设计的状态与恢复

| 状态 | 可见反馈 | 可采取的动作 |
| --- | --- | --- |
| 没有行程／当天为空 | 清楚说明暂无内容，不把自由活动当错误 | 创建／添加／保留空档 |
| 正在生成 | 真实阶段、已有成果、仍在等待的部分 | 离开后继续、查看已有草稿、显式取消 |
| 部分来源失败 | 哪个来源不可读、现有安排依据是否完整 | 继续已有材料、补文字、仅重试该来源 |
| 地点存在歧义 | 具体节点及原因、当前选择、候选地址 | 使用／搜索／待定／移除 |
| 时间或路线冲突 | 冲突节点与影响，不只显示“失败” | 修改此站、采用建议、取消修改 |
| 本地保存失败 | 保留内存与副本；显示未持久化 | 重试；必要时导出当前草稿 |
| 网络不可用 | 行程正文可读，在线信息标更新时间与不可更新 | 离线查看；联网后重试在线核验 |
| 外部地图未安装／无法打开 | 留在当前站点，不丢上下文 | 复制地址／换可用方式 |
| 提醒未授权 | 清楚说明该提醒尚未生效 | 稍后设置或按需到系统开启；行程仍可用 |
| AI 建议过期／应用失败 | 原安排不变，解释需重新核对 | 重新计算受影响部分／放弃建议 |

## 8. 下一版原型的改造顺序与验收

| 顺序 | 要交付的体验 | 验收任务 |
| --- | --- | --- |
| 第一轮：主流程与安全修改 | 单一创建流程、草稿直达结果、概览／行程双分区、列表／地图共享上下文、统一表单与保存规则、基础本机持久化及重开恢复、来源原位返回、AI变更预览和撤销 | 用户只填目的地＋天数可看到草稿；草稿重开仍在；改一半查出处回来内容仍在；AI调整不覆盖固定项，能放弃与撤销 |
| 第二轮：安排可行与途中使用 | 到达／返程／酒店约束、完整站点增删移动、地点与路段状态、后台生成任务续跑、离线阅读、导航与选定提醒 | 下午到达不排上午景点；移站能看路段影响；生成中退出可继续；改期不重复创建提醒，移除站点不遗留未来提醒 |
| 第三轮：补充信息体验 | 预算／天气实际状态、来源片段与原文、导出清单、准备检查 | 未知不显示为已核实；信息更新失败不破坏行程；导出与当前已提交内容一致 |

以下是三轮累计验收任务。下一版交互原型优先演示前六项；真实任务续跑、离线和提醒联动按第二轮能力验证。设计演示不能代替后台或 Android 验收：

1. “杭州三天，日期未定”创建一份草稿，并能稍后补日期。
2. 已订下午到达和第三天下午返程，草稿遵守这两个固定条件。
3. 对一家餐馆保留待定，退出重开后继续处理；列表和地图状态一致。
4. 修改备注，查出处再返回，继续编辑并保存；主动取消则原内容不变。
5. 新增咖啡店、移除一站、跨天移动另一站，看到局部影响并可撤销。
6. “今天晚出发一小时”先看 AI 变化；预约保持；应用后能撤回。
7. 生成中退出／部分失败后继续，已取得材料和手改内容不丢失。
8. 到出行日离线打开下一站地址；选择一项提醒；修改时间只更新原提醒。

上述为下一轮验证目标，不是已经实现或已经通过的用户测试指标。
