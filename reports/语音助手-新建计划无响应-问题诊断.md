# 语音助手"新建计划无响应"问题诊断与修复

**日期**：2026-07-14 | **版本**：V0.1-debug

---

## 一、问题现象

用户在 MY PLAN App 内说"新建计划"，语音助手无任何响应（无提示音、无状态变化）。已确认录音权限已授权。

---

## 二、根因分析

### Bug 1（P0·主因）：权限请求与服务启动的时序竞争

**位置**：`MainActivity.kt` 第 57-71 行

**问题代码：**
```kotlin
// 第 60-64 行（Onboarding 路径）
OnboardingScreen(onStart = {
    if (needsPermission) {
        permissionLauncher.launch(permissionsToRequest.toTypedArray()) // 异步，立即返回
    }
    startVoiceService()  // ← 在权限被授予前就执行了！
})

// 第 66-70 行（非首次启动路径）
LaunchedEffect(Unit) {
    if (needsPermission) {
        permissionLauncher.launch(permissionsToRequest.toTypedArray()) // 异步，立即返回
    }
    startVoiceService()  // ← 同上
}
```

**执行时序：**
```
T0: permissionLauncher.launch() → 系统权限弹窗弹出 → launch() 立即返回
T1: startVoiceService() → checkSelfPermission(RECORD_AUDIO) → PERMISSION_DENIED → 直接 return
T2:（几秒后）用户点击"允许"
T3: 权限已授权，但没有人再调用 startVoiceService()
```

**结论**：`ActivityResultContracts.RequestMultiplePermissions().launch()` 是**异步非阻塞**的。它弹出系统权限对话框后立即返回，不等待用户操作。所以 `startVoiceService()` 始终在用户点击"允许"之前执行，始终被权限检查拦截。此后无人重新触发服务启动。

### Bug 2（P0·辅因）：缺少 FOREGROUND_SERVICE_SPECIAL_USE 权限声明

**位置**：`AndroidManifest.xml`

Android 14（API 34）起，声明 `android:foregroundServiceType="specialUse"` 的 Service 在启动时必须同时在 Manifest 中声明 `<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE" />`。缺少此声明会导致服务启动时抛出 `MissingForegroundServiceTypeException`。

当前 Manifest 已声明 `RECORD_AUDIO` 但缺少 `FOREGROUND_SERVICE_SPECIAL_USE`。

**注意**：`targetSdk = 35`，运行在 Android 15 设备上，此权限**必须**声明。

---

## 三、修复方案

### 修复 1：将 startVoiceService() 移至权限回调中

将 `startVoiceService()` 的调用点从 `launch()` 之后，移至权限结果的回调 Lambda 中。这样无论用户允许还是拒绝，服务启动逻辑都在用户完成操作后执行。

**修改文件**：`MainActivity.kt`

```kotlin
// 改前：
private val permissionLauncher = registerForActivityResult(
    ActivityResultContracts.RequestMultiplePermissions()
) { /* 不管用户允许还是拒绝，继续 */ }

// 改后：
private val permissionLauncher = registerForActivityResult(
    ActivityResultContracts.RequestMultiplePermissions()
) { permissions ->
    // 用户操作完权限对话框后才执行这里
    if (permissions[Manifest.permission.RECORD_AUDIO] == true) {
        VoiceAssistantService.start(this)
    }
}
```

然后在 `LaunchedEffect` 和 `OnboardingScreen.onStart` 中移除 `startVoiceService()` 调用，只保留 `permissionLauncher.launch()`。首次无权限时的流程变为：弹权限框 → 用户允许 → 回调自动启动服务。已有权限时，需要主动调用一次 `startVoiceService()`（因为权限已授予，不会弹框，回调也不会被触发）。

### 修复 2：添加 FOREGROUND_SERVICE_SPECIAL_USE 权限

**修改文件**：`AndroidManifest.xml`

在 `<manifest>` 节点下添加：
```xml
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE" />
```

## 四、验证方法

1. 卸载旧版 → 安装修复版 APK
2. 首次启动应弹出"允许 MY PLAN 录音？"对话框 → 点击"允许"
3. 进入列表页后，说"新建计划"
4. 预期：顶部出现绿色胶囊"正在听..."，并听到 TTS："你好，想创建什么计划？"

## 五、如果修复后仍然不工作

可能的次级原因（优先级由高到低）：

| # | 可能原因 | 排查方法 |
|---|---------|---------|
| 1 | OPPO 禁止后台启动 Service | 检查 Logcat：`VoiceAssistant` TAG。如果看到 `startForegroundService() not allowed` → 需要把 startForegroundService 改为 startService（已在代码中处理了 API 版本分支） |
| 2 | SpeechRecognizer 在线服务不可用 | 检查 Logcat：`STT` TAG。`onError: ERROR_NETWORK` → 尝试在 WiFi 环境下测试，或下载 Google 离线语音包 |
| 3 | TTS 初始化失败 | 检查 Logcat：`TTS` TAG。`TTS初始化失败` 或 `中文TTS不可用` → 需要在系统设置中下载中文 TTS 语音包 |
| 4 | OPPO 杀了前台 Service | 通知栏应显示"MY PLAN · 准备就绪"。如果通知栏没有 → 服务未成功启动，需检查自启动/电池优化设置 |
